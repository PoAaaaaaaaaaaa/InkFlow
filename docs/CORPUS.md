# AI 语料库（v1.3.0）

这一层解决一个具体问题：**通用大模型写中文小说时，稳定地写出「正确但空洞」的文字。**

它们语法正确、标点规范、情节连贯，但每一句都换到任何一本书里也成立。
本模块把「AI 腔」从一种模糊感觉，拆成三层可计算、可注入、可验证的结构。

---

## 三层结构

```
┌──────────────────────────────────────────────────────┐
│  负向层 · SlopLexicon + SlopDetector                  │
│  别写什么：120+ 条 AI 腔词条 + 8 类句式模板            │
│  每条都带「为什么」与「往哪改」                        │
└──────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────┐
│  正向层 · SensoryVault                                │
│  可以写什么：抽象说法 → 具体表现（动作/器物/体感）      │
│  这是「删掉套话之后填什么」的答案                      │
└──────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────┐
│  参照层 · DeconstructLibrary                          │
│  同类作品靠什么留人：5 本已验证，每条带证据与迁移方法   │
└──────────────────────────────────────────────────────┘
              ↓ 由 CorpusEngine 总装
        注入 writeChapter / continueWriting / polish
```

**只有负向清单的写作助手会写出「干净但空洞」的文字。** 三层必须同时在場。

## 一、负向层：AI 腔词库

### 分类

| 分类 | 病灶 | 处理方向 |
|---|---|---|
| 情绪套话 | 给情绪命名（「五味杂陈」）而不是呈现 | 换成动作与体感 |
| 万能环境句 | 换到任何一本书都成立（「空气仿佛凝固了」） | 换成只属于这一场的细节 |
| 空洞副词 | 「缓缓地/深深地/静静地」是节奏填充物 | 直接删，通常句子更好 |
| 转折滥用 | 「然而/与此同时/这一刻」是论文连接词 | 用事件完成转折 |
| 总结腔 | 「总之/由此可见」把读者推出场景 | 删 |
| 模板钩子 | 「而这仅仅是开始」已被用烂 | 落在具体的人/物/数字上 |
| 排比滥用 | 整齐三段排比是 AI 最爱的节奏 | 真人的修辞是不对称的 |
| 抽象名词 | 「某种/一种」是没想清楚的信号 | 想清楚 |
| 身体反应套话 | 「瞳孔骤缩/嘴角勾起」是漫画分镜 | 换成这个人独有的反应 |
| 形容词堆砌 | 两个以上形容词叠同一名词 | 至少删一个 |

### 严重度

- **3（严重）**：一眼 AI。出现即判定走味，必须给出替代方向。
- **2（建议）**：明显走味。
- **1（提示）**：可接受，但高频出现即成节奏问题。

### 句式层

词表抓不到的结构性套话，由正则捕获。「不是……而是……」「与其说……不如说……」
「既是……也是……」这类对偶句，一章用两次以上就是 AI 节奏。

### 检测的两个核心设计

**1. 重叠去重。** 词库里有包含关系：「不禁倒吸一口凉气」含「不禁」，
「深深地看了他一眼」含「深深地」。不去重则一句话被计两次，密度翻倍。
规则：长的胜（更具体），长度相同则严重度高的胜。

**2. 密度 × 置信度。** 风险分不是单纯密度：

```
风险 = 密度分（每千字加权分值） × 样本置信度（按字数阶梯）
```

密度回答「有多脏」，置信度回答「这点样本够不够下结论」。
一段 18 字的文本里出现一个「深深地」，密度是满分级别——
但凭一句话判定整章走味是统计上的越权。所以：

| 样本量 | 置信度 |
|---|---|
| ≥ 300 字 | 1.0（一个完整场景，足以判断） |
| 60 ~ 300 字 | 0.35 ~ 1.0 线性 |
| ≤ 60 字 | 0.35 封底 |

**设计立场：短样本只会被低估，不会被高估。** 误报比漏报更伤作者信任。

## 二、正向层：具体化选词库

组织的维度是「抽象 → 具体」，不是同义词表：

```
愤怒（体感）
  · 把烟按灭在没抽完的位置
  · 放杯子的时候故意放重，然后再放轻
  · 重复对方最后一句话，一字不差
```

覆盖六个感官通道：视觉 / 听觉 / 嗅觉 / 触觉 / 温觉 / 体感。
按题材过滤：古代 / 现代 / 科幻 / 通用。

### 为什么不做同义替换

套话的病灶不是用词，是**信息缺失**。「心中五味杂陈」换不成更好的四字词，
只能换成具体的动作。所以库只给**方向**与**颗粒度示范**，
改写必须由作者或模型完成。

注入提示词时的措辞刻意留了后半句：

> 以上是样例，不是词表。直接照抄会被读者认出来——请写出属于你这一场的具体细节。

如果只说「从下面挑」，模型会照抄；说「照着这个颗粒度自己造」，它才会真的去写。

### 具体度评分

`CorpusEngine.concretenessOf()` 算的是「这段文字里有多少东西能被看见、听见、摸到」：

1. 统计感官锚点：身体部位 + 器物 + 方位词；
2. 统计抽象词：情绪命名 + 概念名词 + 万能副词；
3. 按千字归一后取比值。

不做机器学习：规则能算的东西不该引入不可解释的黑盒，
尤其当作者需要知道「为什么是 42 分」。

## 三、参照层：拆书作品库

拆书的产出**不是剧情梗概**——梗概对写作毫无帮助。
有用的是「这本书靠什么机制留住读者」，因为机制可以迁移到别的题材。

每条拆解包含四个字段：

| 字段 | 作用 |
|---|---|
| aspect | 拆解维度（开篇钩子/金手指设计/节奏结构/信息释放/角色声音/章末钩子/爽点兑现/世界观铺设/真实感锚点） |
| mechanism | 机制本身：可迁移的、与题材无关的做法 |
| evidence | 书中的证据。没有证据的结论只是读后感 |
| transferable | 迁移到别的题材时怎么用——**这一步才是拆书的价值** |

### 数据诚实原则

1. **未核实的书不给结论。** `unverifiedTitles` 里的书在 UI 上显式标为「待补全」，
   而不是拿编造的数据冒充。
2. **样本量不足的书标警示。** 例如《脑机飞升》只有 6 章 1.7 万字，
   它的结论只能用于开篇设计，不能指导百万字结构——`caveat` 字段会把它挡在常规注入之外。
3. **每条结论必须有来源。** `verified = true` 的卡片必须同时有 `source` 与 `findings`，
   这条约束由测试强制。

## 四、总装：CorpusEngine

```kotlin
// 生成正文时注入三层
val block = CorpusEngine.writingBlock(genre = "都市悬疑")

// 单独审稿
val audit = CorpusEngine.audit(text, genre = "科幻末世")
audit.aiFlavorScore   // 0..100，综合 AI 味
audit.concreteness    // 具体度评分
audit.suggestions     // 按当前问题密度给出的选词方向

// 查抽象说法的具体表现
val choice = CorpusEngine.chooseWords("愤怒")
choice?.candidates    // 3 个可直接落笔的写法
```

### 注入位置

| 场景 | 注入内容 | 不注入 |
|---|---|---|
| 生成整章 `writeChapter` | 三层全上（含拆书） | — |
| 智能续写 `continueWriting` | 选词 + 禁忌清单 | 拆书（结构已定，参照无意义） |
| 润色 `polish` | 本文**实际命中**的套话 + 选词 | 无差别清单 |

润色场景的措辞是关键差异：给模型看它这篇实际错在哪，
比糊一长串通用清单有效得多——后者只会得到一次泛泛的重写。

## 五、接入质量层

`QualityEvaluator` 新增第五个维度 `aiFlavor`。

**为什么要单独成维**：AI 腔是一种**独立于其他所有维度**的失败模式。
一段情节连贯、标点规范、句式也符合文风的文字，照样可以是彻底的 AI 腔——
因为它每一句都正确，却没有一句是具体的。

加权方案（AI 腔权重 0.20 是追加的，原有四项相对比例不变）：

| 维度 | 权重 |
|---|---|
| 连贯性 | 0.30 |
| 流畅度 | 0.30 |
| 文风吻合度 | 0.20 |
| 叙事连续性 | 0.20 |
| **AI 腔** | **0.20** |

AI 腔维度实际占总分 0.20/1.20 ≈ 17%。给这个量级是因为：
对长篇网文作者而言「读起来像 AI 写的」是致命伤，
但不该压过连贯性与流畅度这两个更基础的质量维度。

> 此前 `IssueType.AiFlavor` 枚举定义了却从未被使用，
> `AgentPipeline.guessAiFlavor` 也只有 15 个硬编码词。v1.3.0 把两者接上了。

## 六、验证状态

| 项目 | 结果 |
|---|---|
| core 单元测试 | ✅ 125/125 通过（新增 36 条语料库测试 + 5 条质量层 AI 腔测试） |
| app 层 Kotlin 编译 | ✅ 通过（含 R 资源生成 + KSP） |
| APK 打包 | ⏳ 需 x86_64 云端 runner（aapt2 限制，同 ADR-7） |

语料库测试覆盖三条线：

1. **词库完整性**——无重复词条、严重度合法、每条都有 why、
   严重条目必须给替代方向、词表按长度排序；
2. **检测器正确性**——能抓套话、不误伤干净文本、重叠去重、
   短样本保守、偏移量指向真实文本；
3. **数据诚实性**——未核实书目不得带结论、已验证卡片必须有来源、
   每条结论必须可迁移、带样本量警示的书不进常规注入。

## 七、扩展方式

**加一条 AI 腔词条**：在 `SlopLexicon` 对应分类下加 `SlopEntry`。
严重度 3 必须提供 `alternatives`，否则测试不过。

**加一类句式**：在 `SlopLexicon.patterns` 加 `SlopPattern`。
注意避开已有条目的重叠区间，否则会被去重逻辑吃掉。

**加一组具体化词条**：在 `SensoryVault` 加 `VaultEntry`。
`concrete` 里的每条都应是能直接落笔的句子（测试会检查长度 ≥ 4）。

**加一本书**：先在公开渠道核到可靠详情页，再按
`DeconstructCard` 填。**没核到就不要填**——留空是正确结果。
